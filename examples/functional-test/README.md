# 功能验收用例

在单独的测试 Git 仓库中使用这些示例，无需运行代码。插件分析提交快照；只编辑而不提交不会改变当前审查内容。

## 违规与通过

1. 在 IDEA 打开测试仓库，设置中创建默认规则模板并检查。保留业务项目已有规则，示例模板只用于此测试仓库。
2. 将 `good/OrderService.java` 复制到仓库 `src/main/java/demo/OrderService.java`，将 `good/demo.js` 复制到 `web/demo.js`，提交基线。
3. 用 `bad/` 中对应文件替换两文件并提交。
4. 准备当前提交，应出现两个适用文件。先排除 JS，计数应变成 1；确认冻结范围后开始，报告只应覆盖已纳入的 Java 文件。
5. 全部纳入后重新开始，预期模型报告 Java 控制台输出与 JS 全局 eval 两种违反规则的行为。具体返回由所配模型决定，应同时检查覆盖记录。
6. 恢复 `good/` 文件并提交，再准备/执行，预期无上述违规。

## 多仓库

在同一 IDEA 项目登记两个独立测试 Git 根，各按上述方法提交。准备范围应同时列出两根；用顶部“仓库”多选分别只选一根、再全选，确认未选仓库不进入审查。一个根放合法规则，另一个故意选择缺失规则，合法根仍应可执行，失败根和原因必须明确展示。

## 报告处理

点击 **处理** 标记为已确认，再点击 **不处理** 恢复为待处理。重开项目查看历史及筛选，操作顺序应保留。把一次失败报告确认，AI 状态仍应是失败，不应变成检查通过。

## 小人状态

| 动作 | 触发 |
| --- | --- |
| 待机 | 没有适用任务或尚未开始 |
| 挥手 | 准备范围、等待执行、审查中 |
| 开心 | 本批完整完成且没有发现 |
| 眨眼提示 | 本批有发现或部分完成 |
| 困倦 | 失败或取消 |

所有动作都带呼吸和眨眼。困倦不是定时闲置触发。单击小人切换面板，右键可打开报告/设置；拖动四边应正确吸附。
