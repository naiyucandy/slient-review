# 1.1.1 安装与验收指南

安装 `silent-review-1.1.1.zip`，在 IDEA 设置 → Plugins → 齿轮 → Install Plugin from Disk 选 ZIP 后重启。插件仍叫 Silent Review，从 IDEA 2024.1（241）起安装，不再设置 243 上限；新旧 IDE 共用此安装包。实测清单见 [兼容说明](COMPATIBILITY.md)。安装包独立放在 GitHub Releases，源码目录不附安装包。

## 最短流程

设置 → 静默代码检测 → 创建、浏览选择或检查规则 → 填接口/模型/Key → 授权发送 → 应用。Key 不回显，以“已保存/未保存/仅本次会话”状态判断。

打开 Silent Review，准备当前提交，确认纳入文件，开始审查。未提交的编辑不进入此次请求。

## 多 Git 根

在已登记多个 Git 根的 IDEA 项目中准备范围，应出现每个仓库的根、分支、HEAD、基线、变更文件及规则匹配。顶部“仓库”选择器支持多选和全选，未选中的仓库不进入本次审查；单根失败仍可审查其他根。项目根的相对规则文件可作为各根的回退；更具体的仓库规则优先。

准备后取消一个文件的纳入，计数应即时变化，执行后的报告不应包含它的检查记录。准备后若提交或切分支，应要求刷新。审查使用冻结提交；IDEA 原生“included”不是本插件的纳入状态。当前选择粒度为文件。

## 关联上下文与源码定位

规则可引用同一目标提交中的未变更配套文件，或用contextFiles声明关联路径。候选缺失、读取失败、歧义和预算不足都会显示；插件没有固定某个登记规则。详情见 RULE-CONTEXT.md。

报告问题默认打开当前项目源码；证据移动会尝试重定位，已改/删除会提示。查看当时提交是另一个独立入口。

## 报告闭环

对报告点击 **处理** 标记为已确认，点击 **不处理** 恢复为待处理；处理时间、操作者及历史应立即显示并在重开项目后保留。已确认报告仍可筛选。失败或部分完成的报告即使确认，AI 原始状态仍保留。

## 小人

连续点击应展开/收起侧栏。把小人分别拖到四边和四角，不应由左侧跳到右侧或由顶部跳到底部；拖出窗口后应夹紧到对应边。右下吸附后调整窗口大小，应保持对应边缘。

## 示例违规代码

在测试仓库的 `src/main/java/demo/OrderService.java` 使用真实 `System.out.println`，在 `web/demo.js` 使用真实全局 `eval`，提交后准备范围。示例文件位于 `examples/functional-test/`，请仅在测试仓库使用；不需运行这些代码。

## 验证边界与构建

本包通过 SDK 编译、自动化回归及插件结构检查。真实多根工作区、模型返回、密码库跨重启持久化和屏幕缩放需安装后验收，实际结果以报告覆盖信息为准。

```powershell
.\scripts\dev.ps1 -IdeaHome '<IDEA_HOME>'
```

使用 JDK21。默认输出 `build/distributions/`，不含源码 ZIP 的构建缓存和 SDK。
